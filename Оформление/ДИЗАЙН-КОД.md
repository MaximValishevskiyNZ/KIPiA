# Дизайн-код КИПиА

**Характер:** спокойная инженерная документация. Устройство должно стать понятным с первого просмотра: что связано, куда идёт сигнал, что проверить и откуда взято значение.

## Цвета

| Роль | Цвет | Применение |
| --- | --- | --- |
| Основной текст / тёмный фон | `#14283F` | Заголовки, контуры, обложка |
| Измерение и сигнал | `#007F78` | Линии сигнала, расстояния, подтверждённые связи |
| Внимание | `#AF5700` | Ближняя зона, важные ограничения, непроверенная привязка |
| Фон схемы | `#F3F6FA` | Поле рисунка |
| Поверхность карточки | `#FFFFFF` | Блоки устройств и таблиц |
| Вторичный текст | `#526477` | Подписи и метаданные |
| Разделители | `#C8D5E2` | Рамки и вспомогательные линии |

Цвет не заменяет текст: плюс и минус подписаны, BD имеет обозначение, возможная схема помечена словами. Машиночитаемые значения: [tokens.json](tokens.json).

## Текст и структура

- Один H1 на документ; H2 — этап работы; H3 — конкретная ситуация.
- Начало техкарты: задача, применимость, что известно, что проверить.
- Сначала схема и смысл, затем действия, потом критерий результата.
- Названия меню сохраняются как на приборе: `empty calibr. (005)`.
- Формат значений: `0,35 м`, `24 В DC`, `4–20 мА`. В коде и JSON допускается десятичная точка.
- Числа учебного примера прямо подписываются. Неизвестные параметры обозначаются «не установлено», а не правдоподобным значением.
- В таблице подключения обязательно указаны модель, исполнение и источник.
- Для параметра или группы связанных данных приводится документ с разделом/страницей.

## Схемы

**Постоянное:** SVG для электрических схем и геометрии, Mermaid для коротких алгоритмов. SVG хранится рядом с материалом в `media/`; имена отражают назначение. Исходники SVG редактируемые, без зависимости от внешних шрифтов и картинок.

| Элемент | Правило |
| --- | --- |
| Холст | Обычно 1200 × 620; допускается выше для схем с пояснениями |
| Заголовок | 28–32 px, основной цвет |
| Текст | Не менее 18 px; шрифт `DejaVu Sans, Arial, sans-serif` |
| Линии | 2–3 px, плавные скругления |
| Направление | Вход → обработка → выход; стрелки показывают смысл, а не произвольный декор |
| Электрика | Реальные номера клемм; знак земли отделён от сигнального минуса |
| Подпись | Исполнение, границы применимости, ID источника и страница |
| Доступность | SVG содержит `title` и `desc`; Markdown-картинка — осмысленный alt |

Не рисовать общую «схему Prosonic» с конкретными клеммами сразу для нескольких несовместимых исполнений. Условную механику подписывать как предположение, а не заводской чертёж.

## Повторяемый комплект

Для нового прибора: обложка раздела при необходимости → техкарта → схема → диагностика → протокол → источники. Начни с [шаблона устройства](../Шаблоны/Устройство.md) и [SVG-шаблона схемы](схема-шаблон.svg).

GitHub сам оформляет Markdown; цвета и шрифты его интерфейса не переопределяются. Стиль реализован через согласованные заголовки, таблицы, навигацию, схемы и обложку. Для PDF используется та же палитра.

## Перед публикацией

Проверить читаемость рисунка в ширине страницы GitHub и на A4; корректность ссылок; соответствие схемы указанному исполнению; наличие источника у числовых параметров; отсутствие данных, которые выдают пример за реальный объект.
